FRIB final project and live demo

Extract the whole project, then double-click START_FRIB.command on macOS. It automatically installs missing dependencies and models, starts the API and dashboard, and opens the app. Later launches reuse what is already installed. Use START_LIVE_DEMO.command for the separate presentation workspace. Both use Ollama qwen3:8b, sentence-transformers all-MiniLM-L6-v2 and SQLite. First setup needs internet and several gigabytes of disk space. SETUP_LOCAL_AI.command is an optional setup/repair command; it is not a required first step. Read MACOS_SETUP.md for details.

Normal records are saved in FRIB_Decision_Support/data-local-ai. Demo records are saved in Demo_Workspace_AI. When data/frib.db exists and data-local-ai does not, first setup copies the normal workspace and re-embeds its approved chunks. The source is retained; an existing destination is never overwritten. The old Demo_Workspace is not migrated automatically, so upload presentation procedures into Demo_Workspace_AI when needed. Missing models produce an actionable error; the launchers do not fall back to mocks.

On Windows, use START_FRIB.cmd or START_LIVE_DEMO.cmd. Install Ollama and the configured model if the launcher reports that they are missing; the automatic private Ollama installer is for macOS. Keep the newest launcher window open while using the app. Opening another normal FRIB launcher safely replaces the older FRIB workspace across project copies; ordinary switching does not require Ctrl+C. Use Ctrl+C in a terminal launch when you want to stop it yourself.

Choose Start tutorial on Home for a guided walkthrough, or read FIRST_STEPS.md. The compact tutorial stays on Home. Return to Home → Continue tutorial to resume, or Replay tutorial to start again. For the presentation, follow Live_Demo_Data/README.md. Upload files from datasets and procedures, or use Addition items → Try a new demo presets. These are fictional training inputs. Nothing is imported automatically; approving a fictional procedure is an explicit exercise, not facility approval.

On macOS, the startup window shows the actual preparation stages. The newest normal launch has priority: it safely shuts down older FRIB workers and opens the selected project with that project's own saved records. Installed models and saved files are retained. Keep the newest window open and choose Stop workspace when finished; use Show details and Retry if startup needs attention. Queued updates for the selected project apply after the handoff. Installation checks and maintenance commands do not take over the running workspace. Read FRIB_Decision_Support/docs/SINGLE_INSTANCE_STARTUP.md for details. Within the app, bottom Next / Back buttons keep your place. Citation bubbles labeled S1, S2, S3 open the matching source beside the answer, with revision and page information when recorded. Details begin collapsed. Draft sources also use expandable bubbles.

FRIB_Decision_Support contains source, configuration, tests, guides and reference PDFs. Live_Demo_Data contains 13 datasets, seven procedure files and mapping references. Verification contains historical startup and bundle reports. These reports describe their recorded runs, not a guarantee about a later model's answer.

RUN_DEMO_CHECKS.command (or .cmd) checks the supplied fixture pack in disposable storage using explicit test doubles and writes Demo_Check_Results. Those tests remain separate from the real-model application. Saved records, model weights and installed packages are excluded from source archives. On macOS, AI files persist in ~/Library/Application Support/FRIB and are reused by fresh project copies on that Mac. A different Mac needs its own initial setup. Removing that folder or selecting a new model requires downloading the missing files again.

The sidebar numbers Add data through Review & approve as 1–5. Addition items combines System status, Settings, Help and Try a new demo, displaying one section at a time while retaining the original tools. The supplied run animation loops bouncing balls until the request ends, then holds a checkmark after success; failures keep their error state. AI requests without reported intermediate progress use a clearly labeled estimated percentage and elapsed time, capped at 95% until successful completion reaches 100%; bulk transfers and file jobs show measured percentages. Read FRIB_Decision_Support/docs/UI_NOVEMBER_UPDATE.md for the current interface details.
